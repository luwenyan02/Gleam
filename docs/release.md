## Android 应用内检查新版

入口为「我的 → 关于和帮助 → 关于拾光」。手册整理预览已移除设置中的重复入口；此前版本也可从「设置 → 关于拾光 → 检查新版」进入。仅 Android 提供，点击检查才访问 GitHub，不在启动时自动检查。

仓库保持私有。用户在 GitHub 创建 Fine-grained personal access token，Repository access 只选择 `luwenyan02/Gleam`，Repository permissions 的 Contents 设为 Read-only（Metadata 按 GitHub 默认只读），并选择合适有效期。在 App 的「GitHub 访问设置」填入，点击「保存并验证」；过期后在此替换。不要把 Token 发到聊天、写入 APK 或加入 Git。Token 由 Android Keystore 加密，仅供原生更新通道读取，不包含在 `.skbak` 备份中。

更新源为该仓库 `/releases/latest`，只使用正式 Release。每次发布递增 `package.json` 的三段版本（minor/patch 均小于 100，与现有 Android versionCode 规则一致），标签为 `vX.Y.Z`，并同时附上原 F979 证书签名的 `Gleam-vX.Y.Z.apk` 和 `Gleam-vX.Y.Z.apk.sha256`。校验文件使用 `sha256sum` 格式，文件名必须与 APK 一致；不能使用 CI 无签名包。先在草稿中上传完整附件，再将 Release 正式发布并设为 latest，避免用户检查时看到不完整附件。此说明不自动授权创建或改动 Release。

App 比较手机实际安装的 versionCode，只接受更高版本。关于页使用同一按钮依次显示「检查更新 → 下载更新 → 更新」，下载时背景填充进度，校验成功后才允许安装。下载经原生 HTTPS 通道；Token 仅发送给固定 GitHub API，不转发给附件 CDN。下载至应用缓存，最多 150 MB，核验文件大小、SHA-256、包名、版本、当前签名和原 F979 签名；取消或失败清理半成品。点击「更新」后交给 Android 系统确认；若系统要求允许此来源安装，授权后返回再点「更新」。拒绝或取消安装不会自动重试，也不表示更新成功。

关闭关于页后已开始的下载可继续。再次进入或重启后先检查本地包：重新核验大小、SHA-256、包名、版本与签名，通过后直接显示「更新」，无需联网或重新下载。未完成的任务先停止并清理半包；无可用包、文件损坏或目标版本已安装时回到「检查更新」，点击后才访问 GitHub。原生缓存同时原子保存不含凭据的版本及校验信息，缓存不能当作持久备份。

真实私有 Token 下载、安装来源授权及覆盖安装仍需 Android 手机验收；浏览器模拟桥和 JVM 校验测试不能替代这一步。

通过 GitHub 维护源码与文档。仅在获得发布授权后交付最终合并提交对应的 Android 安装包；安装包与校验文件通过 GitHub Releases 分发，不进入源码历史。环境维护不会补发历史版本或调整历史 Release。

## GitHub 发布

1. 完成适用测试、浏览器验收与敏感信息检查，更新文档与验证记录，再将本轮分支合入 `main`。核对远端 `main` 的最终提交及该提交的 GitHub CI；合并后的相关检查须重跑，不能用旧提交的通过结果代替。
2. 从同一最终提交执行 `npm run build:android`，将核验通过的 APK 保存为项目根目录 `release/Gleam-vX.Y.Z.apk`（`release/` 被 Git 忽略），生成对应 SHA-256 校验文件。签名材料只能留在受控构建环境中，不得上传为 Release 附件。
3. 核对版本标签与 `package.json` 一致，并指向构建所用的最终提交。创建对应 GitHub Release，只附本轮 APK 与校验文件；发布说明列出源码提交、已运行检查、升级备份提示和仍待验证的项目。
4. 若真机验收未完成，Release 标题与说明明确写“候选版”，并设为预发布；不得宣布正式验收通过。未完成或受阻的检查如实列出，不复用历史测试数量。
5. 上传后核对 Release 标签、附件名称与大小，并下载附件复核 SHA-256，确认与本地已核验产物一致后再提供下载链接。候选预发布不保证出现在 GitHub 的 `/releases/latest`，交付时使用已验证的具体 Release 链接。

当前 `.github/workflows/ci.yml` 运行网页、完整浏览器、精确历史资源升级诊断与 Android 单元测试，并在显式测试开关下生成无签名 APK 和同次网页资源。签名资料不进入 CI；受控本地环境对最终 main 的 CI 产物核对提交/树、版本、每个网页资源后再用原证书签名，复核唯一证书、对齐、原始条目不变及敏感信息。CI 通过不等于手机验收。另行妥善保存已交付安装包的本地副本。

## 功能边界

- 当前 Android 交付流程针对 APK；PWA 可使用网页生产构建。仓库没有 iOS、Windows 或 macOS 原生安装包工程。
- 实时语音仅在配置了本机中转的开发网页版中可用，Android 安装包与离线 PWA 不包含中转服务，见[实时语音说明](REALTIME_VOICE.md)。
- Android 百炼短语音使用所选百炼 Key 原生直连，不依赖开发中转；转写与文字草稿分别同意，入账需人工确认。1.10.7 短语音与界面已有用户手机验收；整合版本、全部权限中断组合及升级缓存自动修复不由该验收自动覆盖，见[短语音记账](SHORT_VOICE_ENTRY.md)。
