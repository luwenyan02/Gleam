# 可核对的账本趋势与分类分析

拾光仍是本地优先的完整记账与生活记录应用。本功能只读现有账本，不新增账户体系、独立余额、服务端、长期 AI 记忆或自动操作框架。

## 使用方式

在「拾光 → 和拾光聊聊」点击「分析消费」，或输入明确的本人账本查询。范围抽屉提供三种固定方式：

- **单月分类**：所选月的支出、退款、报销口径与分类构成
- **对比上月**：所选月及紧邻的前一个月，差额比较这两个月
- **近 6 月**：截至所选月的六个连续月份；差额明确比较最早与最后一个月，不把它标成环比

月份、自然月／财务月、是否包含收入都能手选。抽屉先在设备上列出全部实际日期范围、整数分计算的金额、笔数与发送目的地，用户确认后才请求配置的模型。手选范围在当前会话内保留，用于重试和重新回答；每次仍重新确认。

## 账务与数值

- 金额保持整数分，货币为人民币；周期是设备本地时间的 `[from,to)`，财务月遵循设置中的 1—28 日起始日
- 退款在退款日期冲抵支出；冲抵模式下，已到账报销追溯到原支出月份；计收入模式按到账日期计收入。两种模式不能混作现金流
- 转账、借贷本金、信用卡还款不计收支；回收站账单不参与分析。对账调整继续沿用现有收支处理
- 原始支出、退款、报销、净支出与收入分别列示；支出笔数和退款笔数分开，分类笔数包含退款。报销计收入时，收入笔数包括对应的到账事件
- 分类沿用父类合并，并保留未知分类、同名但不同 ID 的分类及 12 项之后的合并类别；分类金额和笔数守恒
- 变化率为 `(末期净支出−基期净支出)÷基期净支出`，本机精确运算后四舍五入到两位小数。基期无支出／退款、基期为零、任一期负净支出，或比率超出精确表示范围时，仅列差额并说明原因
- 分类占比仅在总净支出为正且所有原始分类非负时展示；隐藏在合并类别内的负分类同样禁用占比。四舍五入后占比总和可能不等于 100%
- 空月保留零金额和零笔数；整个所选范围没有可分析账单时，不发送模型请求

这些数值描述分析时已经记入账本的数据，不证明某月记录完整，也不预测未来消费。

## 本机证据与追问

成功的分析回复附「本机核对数据」卡。逐月金额、所选月分类与可选收入都可打开对应的本机明细。明细按源账单身份筛选；同名分类不混淆，报销到账可回到原支出。大结果分批显示，点击原账单进入现有只读详情。

卡片和原始证据快照只在当前页面内存中存在，不写入聊天草稿或备份。聊天文本仍按既有规则保存在本机；重新打开会话时，可重新回答并确认以获取新的核对卡。若账本、类别、时间、财务月规则或报销口径改变，即使汇总金额恰好相同，旧证据也不会继续当作当前账单使用。

每张成功结果卡恰有两个本机规则生成的继续分析选项，选择当前方式以外的另外两种方式，保留该结果的截止月、月份口径和收入选择。点击后展示新的范围预览；新范围、重试和重新回答都不能复用旧授权。按钮不会由模型文字生成，不自动改账，且不会清空输入框中尚未发送的生活聊天草稿。

## 隐私与失败处理

外发只有这次问题和经过预览的聚合结果。不会携带原始流水、内部交易 ID、账户名／余额、商家、备注、标签、凭证、照片、生活记录或旧聊天。分类名称本身属于选定聚合数据，会发送。

授权绑定问题、范围、摘要和服务／模型目的地，只能使用一次。取消、失败与重试均需新确认；请求返回后再次检查账本和目的地，变化时丢弃迟到结果。核对明细始终留在本机，不触发模型请求。已到达服务方的数据不能通过取消撤回。

AI 只解释所选聚合信息，提示词要求不编造金额、百分比、动机或扩大范围。AI 的自然语言仍可能有误，应以本机核对数据和原账单为准。本功能不会将模型输出转成账务命令。

## 验证范围

- 单元测试覆盖本机聚合、范围约束、安全数值、一次性授权、请求期间的数据及目的地变化
- 独立离线 oracle 使用 BigInt 复算，跨 UTC、上海与纽约时区；不调用生产金额函数作为正确答案
- 真实浏览器用虚构账目和本地模拟响应检查 360、390、430px 与桌面宽度，涵盖取消／返回、重试、手选范围、证据、追问与状态变化
- 没有调用真实模型，没有验证模型表达质量，也没有进行 Android 真机安装、升级、输入法、手势或读屏验收
