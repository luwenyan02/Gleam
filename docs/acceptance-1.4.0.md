# v1.4.0 借贷账户化验收

日期：2026-09-07。范围：借贷使用应收应付账户、双边本金流水，以及对应的挖财导入导出。本版本为本地候选版，不代表完成 Android 真机综合验收。

## 实际效果

| 操作 | 资金账户 | 应收应付账户 | 收支／净资产本金净变化 |
| --- | --- | --- | --- |
| 借出 | 减少 | 增加，应收为正 | 0 |
| 借入 | 增加 | 减少，应付为负 | 0 |
| 还款 | 减少 | 增加，应付减少 | 0 |
| 收款 | 增加 | 减少，应收减少 | 0 |

表中假定两侧均按账户设置纳入净资产；若主动排除某个隐藏账户，当前净资产与历史趋势都只计算已纳入的账户。

账户页、“我的 → 应收应付”和记账选择器使用同一组账户。新建往来会直接创建应收应付账户；从账户详情进入、编辑和再记可还原两端，包括明确指定或原记录关联的隐藏账户。默认选择列表仍隐藏其他隐藏账户。

## 验证证据

- 56 项单元测试通过：四类双边影响、真实 Dexie 编辑/删除/恢复/导入回滚、同名账户隔离、隐藏账户纳入口径、借贷查重、挖财两种格式、外币互校与特殊名称往返等。
- 完整 9 组浏览器脚本通过；新借贷闭环在 360/390/430px 与桌面分别验证资金及应收应付余额、流水、详情入口、隐藏账户、编辑和再记。
- 挖财虚构样例首次导入 8 条、重复导入跳过 8 条、导出读回跳过 8 条；普通转账允许映射应收应付账户，有跨角色同名歧义时显示分组并需要明确选择，确认后立即允许开始导入。
- 冒号、逗号、引号账户名采用可逆引用格式；单资金账户名称含冒号时不误判为双边金额列表。
- 类型检查、生产构建、敏感信息扫描与补丁格式检查通过。
- 规格审查与代码质量复核均通过；审查发现的隐藏账户、净资产口径、歧义确认与特殊名称问题已修复并有回归测试。
- Android release 构建通过。原生与网页版本同为 1.4.0，20 个内嵌网页文件与最终 dist 逐字节一致，原发布证书签名有效。

## 数据与交付边界

- 按用户确认，旧数据仅为测试数据：本轮不做对象迁移，不对用户正在使用的账本执行清空或备份。旧 `loanContacts` 表仅作为未使用的历史容器保留，新业务不读写它。
- 旧独立对象测试流水不会自动成为应收应付账户流水；如需继续使用，请重新选择双账户录入。旧版备份不承诺自动转换该结构。
- 自动测试、导入导出与截图均在隔离环境使用虚构数据；没有处理用户真实账目或凭据。
- 本地预览沿用 `http://127.0.0.1:4173/`；候选包位于 `.tmp/artifacts/releases/Gleam-v1.4.0-candidate.apk`。不推送 GitHub。
- 未连接 Android 设备；覆盖安装、真实键盘、系统返回、TalkBack 和手机备份恢复仍需复验。原生单元测试当前仅为基础样例，不能替代设备验收。
- 现存 Vite 分块/WebDAV 导入提示、Gradle flatDir/弃用提示未阻断构建，不在本轮扩展处理。
