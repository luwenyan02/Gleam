# 拾光双向实时语音

入口：拾光 → 和拾光聊聊 → 输入区“语音聊”。

## Android

复用「AI 设置」中测试通过的百炼语音 Key、地域、业务空间与固定模型 `qwen3.8-omni-flash-realtime`。共享文字 Key 和独立语音 Key 均沿用原设置规则，语音面板不再填写配置；尚未验证时只提示前往 AI 设置。测试连接只验证原设置的鉴权和配置，不代表手机收音、播报或服务质量已通过验收。

点「语音聊」后，只在当前聊天输入框上显示半透明操作层，不打开抽屉、不遮暗聊天记录；上方仍可阅读、滚动和复制。点击「开始语音」才申请系统麦克风权限并连接。看到「正在听」后直接说话，停顿后拾光自动回答；可继续开口或点「打断」停止播报，也可静音／开启麦克风、结束语音。连接中可取消。关闭语音层、系统返回、进入后台、音频焦点被电话等占用、连接失败或配置变更，都会关闭连接并释放收音和播报；回到前台不会自动录音。连接超时30秒，单次最多5分钟，可主动重新开始。

操作区图标随连接、收音和播报状态播放不同动画，待机、静音、结束时静止；系统减少动态效果时停用动画。动画用于提示状态，不模拟麦克风音量。结束／取消连接会关闭语音层、恢复文字输入和入口焦点，文字草稿与待发送照片保留。语音层沿用返回历史，Escape、Android返回和浏览器返回先关闭语音，前进不会重启。通话中暂时停用新聊天、设置、整理、重新回答等会改变会话的操作，复制和阅读保留。

用户转写按服务端 `text + stash` 替换当前预览，助手转写按增量追加；文字直接更新主聊天的同一条气泡，没有第二份转录面板。最终结果覆盖临时文字，按消息ID去重并隔离最终完成后、打断后与旧会话的迟到数据；可以保留结束前尚未完成的转录片段，保存为正式生活记录前仍须核对。界面更新按动画帧合并，沿用本地草稿保存；退出前立即采用本帧最后的文字，重新进入或重启不会自动录音。阅读旧消息时不强制跳到底部。

播报继续使用自然口语。完整的较长回复（当前至少120字）由 AI 设置中的文字模型按需排为 Markdown，在原气泡内更新，不新建消息、不再次播报。优先分段，必要时强调、引用、代码、标题、列表或表格，不套固定模板；短句、已有 Markdown 结构、被打断或未完成的回复不额外请求。Android 须收到成功完成且待播声音已播完才标记完整；开发网页以当前回复的成功完成事件为界。旧版原生桥没有完成标记时仍保留转写，不猜测完成状态。

开始前按用户指定显示「声音发送至百炼，长回复会通过模型加工排版」；文字目的地固定为本次开始前的配置，后续改配置不会把文字发送到新的服务。排版请求每次只发送该条助手原始转写，不携带用户问题、已有聊天、照片、录音或账本，不再次联网搜索，也不补造来源。排版串行、同一原文只尝试一次；失败保留原文。结束语音立即释放音频，已完成回复的排版可在当前聊天内继续；退出聊天、进入后台或关闭生活 AI 会取消待处理排版，迟到结果不回写其他会话。搜索状态和来源独立保存在原消息上，排版不会覆盖。

消息 `content` 始终是原始转写，供后续聊天与整理使用；可选的 `voiceDisplay` 只用于渲染和复制，沿用安全 Markdown 渲染，HTML不会作为可执行内容插入。两份文字随草稿、正式对话记录和备份保留，恢复时不自动重试排版。排版仍是模型生成的展示稿，需核对，不替代原文或服务实际执行结果。

Android 原生通过受限的百炼 WebSocket 建连，收到匹配的双向会话确认后才开启16kHz单声道PCM收音，以24kHz单声道PCM播报；不依赖开发服务器或浏览器麦克风。服务端VAD判断说话与停顿，设备优先使用通信音源和可用回声消除。打断会清空本地待播声音、取消在途回复，丢弃该回复的迟到音频。两个语音记账入口与语音聊共用麦克风占用互斥，不能同时录音。

Key和已验证配置始终留在原生加密存储中，JS只接收配置是否可用、会话状态、返回文字与结构化搜索结果。语音只发送本轮声音与对话提示，不发送已有文字聊天、照片或账本，不保存音频文件。返回转录保留在本地当前聊天，用户「整理」并确认草稿后才保存为正式记录；重启语音不上传旧上下文。

## 实时语音联网搜索

Qwen3.8-Omni-Flash-Realtime 支持百炼内置搜索。本次修复原 Android 会话中显式 `enable_search: false` 及错误的「未提供联网工具」提示词；在 `session.update` 中启用 `enable_search: true` 和 `search_options: {enable_source: true}`，不同时配置不兼容的 `tools`。原生确认服务端已开启搜索后才采集声音；开发网页同样申请搜索，服务端明确关闭时结束连接并提示重连。Qwen3.5-Omni-Realtime 开发模型也按已公开能力启用，旧Qwen-Audio不推断搜索能力。提示词附设备日期，天气等实时问题可按需搜索，保留自然口语。

每轮以 `response.done.response.usage.plugins.search.count` 确认实际使用：正整数为已搜索，零为未使用，缺少或非法计量为「本次搜索状态未返回」，不会从正文猜测。申请返回来源后，只读取服务端结构化 `search_info.search_results`／`search_results` 中的HTTP(S)链接，去重、限制12条并过滤带凭据或可执行链接；不解析口语或Markdown中的URL。没有可用来源时明确显示「已联网搜索，未返回可用来源」。官方文档公开了来源开关及搜索计量，但未详细展开实时来源列表结构；兼容字段经合成事件验证，实际账号的返回字段和搜索质量仍需实测。

状态与来源按回复ID、消息ID隔离，打断后及旧会话迟到的完成事件不被当作新回复的搜索结果；随原始转写、草稿、正式记录及备份保存，长回复排版和后续转写保留已有来源。来源由用户明确展开、点击，不预取网页或图标。搜索由百炼处理查询，费用遵循服务商规则；帮助说明保留，操作区不额外展开配置。

协议依据：百炼[客户端事件](https://help.aliyun.com/zh/model-studio/client-events)中的搜索开关与来源选项，以及[服务端事件](https://help.aliyun.com/zh/model-studio/server-events)中的搜索使用计量（2026-10-21核对）。

单句语音记账仍见 [手机语音记账](SHORT_VOICE_ENTRY.md)，其滑选、转写和人工保存流程保持独立。

## 开发网页版

本地开发网页保留WebRTC通道，Vite只中转SDP建连鉴权。日常预览使用 [OrbStack 常驻服务](LOCAL_PREVIEW.md)，根目录执行 `sh scripts/preview-local.sh up`；不另外占用5173。

在服务进程环境中设置 `DASHSCOPE_API_KEY` 和 `DASHSCOPE_WORKSPACE_ID`；业务空间也可来自Git忽略的 `app/.env.local`（不是Key）。语音面板自动读取配置，不再出现地域／模型／业务空间表单。使用上述固定实时模型，地域沿用应用语音设置；账号在该地域的权限以实际服务返回为准。更改进程变量需重启服务，不要将Key写入源文件、`VITE_`变量或Git。

中转只在Vite开发模式启用，仅接受同源回环请求和指定请求头，出站固定百炼专属域名；Key只留在Node进程，错误不回显远端正文，不记录SDP、语音或转录日志。生产网页和离线PWA不包含此中转，会提示使用APP；Android使用上面的原生通道。不要将开发服务暴露到公网。

接口依据：[百炼Realtime指南](https://help.aliyun.com/zh/model-studio/realtime)、[客户端事件](https://help.aliyun.com/zh/model-studio/client-events)、[服务端事件](https://help.aliyun.com/zh/model-studio/server-events)。实际手机的权限、扬声器／耳机、回声、打断延迟、系统切换和升级保留配置需真机验收，合成桥与JVM测试不能替代。
