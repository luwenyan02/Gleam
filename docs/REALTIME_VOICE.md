# 拾光双向实时语音

入口：拾光 → 和拾光聊聊 → 输入区“语音聊”。

## Android

复用「AI 设置」中测试通过的百炼语音 Key、地域、业务空间与固定模型 `qwen3.8-omni-flash-realtime`。共享文字 Key 和独立语音 Key 均沿用原设置规则，语音面板不再填写配置；尚未验证时只提示前往 AI 设置。测试连接只验证原设置的鉴权和配置，不代表手机收音、播报或服务质量已通过验收。

点击「开始语音」才申请系统麦克风权限并连接。看到「正在听」后直接说话，停顿后拾光自动回答；可继续开口或点「打断回复」停止播报，也可静音／开启麦克风、结束语音。连接中可取消。关闭面板、系统返回、进入后台、音频焦点被电话等占用、连接失败或配置变更，都会关闭连接并释放收音和播报；回到前台不会自动录音。连接超时30秒，单次最多5分钟，可主动重新开始。

Android 原生通过受限的百炼 WebSocket 建连，收到匹配的双向会话确认后才开启16kHz单声道PCM收音，以24kHz单声道PCM播报；不依赖开发服务器或浏览器麦克风。服务端VAD判断说话与停顿，设备优先使用通信音源和可用回声消除。打断会清空本地待播声音、取消在途回复，丢弃该回复的迟到音频。两个语音记账入口与语音聊共用麦克风占用互斥，不能同时录音。

Key和已验证配置始终留在原生加密存储中，JS只接收配置是否可用、会话状态和返回文字。语音只发送本轮声音与固定对话提示，不发送已有文字聊天、照片或账本，不保存音频文件。返回转录保留在本地当前聊天，用户「整理」并确认草稿后才保存为正式记录；重启语音不上传旧上下文。语音尚未挂载搜索工具，不能沿用文字聊天的联网状态。

单句语音记账仍见 [手机语音记账](SHORT_VOICE_ENTRY.md)，其滑选、转写和人工保存流程保持独立。

## 开发网页版

本地开发网页保留WebRTC通道，Vite只中转SDP建连鉴权。日常预览使用 [OrbStack 常驻服务](LOCAL_PREVIEW.md)，根目录执行 `sh scripts/preview-local.sh up`；不另外占用5173。

在服务进程环境中设置 `DASHSCOPE_API_KEY` 和 `DASHSCOPE_WORKSPACE_ID`；业务空间也可来自Git忽略的 `app/.env.local`（不是Key）。语音面板自动读取配置，不再出现地域／模型／业务空间表单。使用上述固定实时模型，地域沿用应用语音设置；账号在该地域的权限以实际服务返回为准。更改进程变量需重启服务，不要将Key写入源文件、`VITE_`变量或Git。

中转只在Vite开发模式启用，仅接受同源回环请求和指定请求头，出站固定百炼专属域名；Key只留在Node进程，错误不回显远端正文，不记录SDP、语音或转录日志。生产网页和离线PWA不包含此中转，会提示使用APP；Android使用上面的原生通道。不要将开发服务暴露到公网。

接口依据：[百炼Realtime指南](https://help.aliyun.com/zh/model-studio/realtime)、[客户端事件](https://help.aliyun.com/zh/model-studio/client-events)、[服务端事件](https://help.aliyun.com/zh/model-studio/server-events)。实际手机的权限、扬声器／耳机、回声、打断延迟、系统切换和升级保留配置需真机验收，合成桥与JVM测试不能替代。
