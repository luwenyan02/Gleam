# AI 账本分析离线评测

本评测检验本机账本摘要、整数分账务口径、逐次授权和模拟出站契约。仅使用虚构数据；不读取个人账本，不调用真实模型，不需要 API 密钥，不以模拟回复代替真实模型质量验收。

## 运行

在 `app/` 执行：

```bash
npm ci --ignore-scripts
npm run test:unit
npm run test:ai-eval
npm run build
```

`test:ai-eval` 在独立子进程分别使用 `UTC`、`Asia/Shanghai`、`America/New_York`。报告写入仓库 `.tmp/ai-eval/`，不提交 Git；CI 保存报告为构建附件。报告记录实际提交、工作区是否有修改、oracle 版本、运行时间、时区、用例分组及失败详情、执行数量和模拟/被拦截请求数量。空集合、跳过用例、缺失或损坏报告、遥测缺失、子进程失败和意外网络请求均不能判定为通过。

评测出站默认拒绝；允许的请求也只能进入当前用例明确安装的 `https://*.invalid` 模拟处理器，没有真实网络回退。运行器不继承模型凭据。单元评测没有把模型工具选择放进被测路径，报告标记 tool selection 为不适用；actual model 标记未测试。

## 独立正确性基准

- 固定观察时点为北京时间 `2026-10-10 12:00`
- `app/tests/ai-eval/fixture.ts` 提供 18 笔完全虚构交易及独立复算的固定答案
- `oracle.ts` 只引用生产结构类型，不调用生产的金额、报表、账本事件、日期范围或账户余额计算函数；金额使用 BigInt 累加，转回 number 时检查安全整数范围
- 生产摘要与独立答案比较；与现有报表的相互一致性只是补充，不能代替独立答案
- 用真实记账仓库写入虚构交易，再核验账户余额、退款关联删除和恢复。边界/损坏数据测试直接写入隔离的测试数据库，避免写入校验掩盖读取防护

## 覆盖与边界

- 自然月/财务月、起始日 1/20/28、`[from,to)`、前后 1 毫秒、闰年、跨年、纽约夏令时
- 退款、跨月部分报销、原支出与到账日期、转账/借贷本金、回收站、真实仓库删除恢复与余额
- 父子分类、未知分类、同名但不同 ID 的分类、12 项上限后的“其他”金额及笔数守恒
- 分数金额、非有限数、不安全整数及累加溢出、收入与报销安全校验
- 审阅摘要与实际模拟发送一致、默认不含收入、账户/备注/商家/标签/照片/旧对话等隐私哨兵
- 一次性 grant 的问题/范围/目的地绑定、修改后重新确认、撤销、取消、失败及重试不能复用授权；摘要和发送不得写入账本

这些离线测试不证明真实模型能正确分析、不会幻觉或遵守提示词，也不代表用户界面按钮或 Android 真机已验收。Cancel/Back 对话框等真实交互由现有浏览器回归测试单独覆盖；本评测只验证其底层授权和请求生命周期契约。无需为纯测试阶段重新发布 APK 或更换签名。

### 已知的保守数值限制

生产代码会先把原金额和报销金额相加进行安全整数检查。因此 MAX_SAFE_INTEGER 分的原支出加 1 分报销，即使净额仍安全，也会被保守拒绝。评测明确记录此边界，不把它误报为与精确 BigInt oracle 一致；本阶段没有修改生产金额规则。

## 趋势与分类扩展（oracle v2）

`trend-category.test.ts` 增加 159 个独立用例，完整集合为 242 个／时区。它覆盖所选月结束的 2／6 月范围、首末差额、两位百分比与极端显示精度、空／零／负基准、自然月和起始日 1／20／28 的财务月、跨年／闰月／纽约 DST、原始分类合并前的负数、同名／未知／其他类别证据、一次性授权以及失败／取消／迟到结果。正确答案来自独立 BigInt oracle，生产摘要只作为被测输出。

本机证据用例核验实际源账单 ID，包括报销到账对应的原支出、同额换源、同额改日期与子类名称变化；这些 ID 不出现在模型请求中。两条规则追问保留已成功结果的月份、周期和收入选择，任何新请求重新预览。无自动账务写入。

三时区完整离线运行应有 726 次执行、51 次拦截的模拟请求及零真实／未模拟请求；精确次数以该提交报告为准。oracle 版本为 `synthetic-ledger-v2`。界面交互另由 `test_chat_ledger_analysis.py` 使用虚构数据在真实浏览器中检查，模型输出正确性仍标记为未测试。
